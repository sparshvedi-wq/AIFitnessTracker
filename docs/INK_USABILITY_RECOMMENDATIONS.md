# Ink usability review — suggestions, not a redesign

The dark Ink palette, warm paper cards, serif headings and blue accents already form a recognizable design language. Keep them. The changes below are recommendations for a later pass, not additional features silently added with this work.

| Area | Current friction | Suggested change | Why it helps |
| --- | --- | --- | --- |
| Home hierarchy | A large score and stats sit above the next action. | Put the next session directly below the greeting/check-in cue; make the score a secondary progress module. | Someone opening the app at the gym should immediately recognize their next action. |
| Score credibility | “Growth” is based on logged lifting volume, not measured muscle growth. | Rename to “Training volume trend”; explain the score's two inputs in a short disclosure. | Precise labels feel trustworthy and avoid an AI-generated promise the app cannot establish. |
| Start controls | Several entry points historically used an ambiguous “Begin.” | Keep one primary “Plan my session” route and one clear “Start session” action in the player. | Users can distinguish choosing a plan from beginning a session. This distinction was implemented here. |
| Train structure | Eight starter plans look equally prominent despite different purposes. | Keep warmups/recommendation at the top; collapse starters under “Browse routines,” with saved routines before templates. | Reduces the amount to scan before a frequent action. |
| Planning preview | Decisions, rationale, cues and prescription can become a wall of text. | Show name + dose first, with explanations and cues expandable per exercise. | Supports quick decisions and deep inspection in the same layout. This disclosure was implemented for the new planner. |
| Workout controls | Logging competes with form, history and plan edits. | Keep Log set as the strongest action; put Swap/Skip beside the current exercise and leave advanced editing in options. | The frequent action becomes stable and easy to reach with one thumb. |
| Timer language | “Skip rest” sounds like hurrying is desirable. | Use readiness language and keep elapsed duration out of the primary player. | A calmer session better fits training at your own pace. Implemented in this pass. |
| Form help | The current “Form” play icon can imply a demonstration video, while some exercises have only text/abstract figures. | Label it “How to” until real demonstrations exist; show required equipment and common adjustments. | Sets an honest expectation and makes guidance feel deliberately written. |
| Session finish | Score changes, records, sharing, effort and saving all compete at the end. | Lead with “Session saved” only after persistence succeeds; make effort one optional row, sharing secondary, and time collapsible. | Clear closure matters more than a celebratory dashboard. |
| Photos | Legacy photo functionality did not arrive with the Ink branch. | Keep one due-date card on Home and the permanent check-in entry in You; add an opt-in before/after comparison later. | Prevents check-ins becoming a hidden feature. The date card and entries were restored here. |
| Check-in language | “AI found a smaller side” can sound like a diagnosis or certainty. | Use a visible observation + uncertainty + user confirmation, with a separate real movement comparison for side work. | Makes personalization understandable and avoids false authority. Implemented for confirmed focus here. |
| Equipment changes | Home setup can drift as equipment is borrowed or unavailable. | Offer a small “Edit home setup” link directly in session preparation instead of making users find account settings. | The correction happens where the constraint matters. |
| Empty history | Large blank graphs and placeholders can look unfinished. | Show a small example of what will appear after one workout, labelled as an example, with one start action. | Teaches the feature without pretending the user has data. |
| History navigation | A long activity list makes it hard to return to a particular lift or warmup. | Add compact All / Strength / Warmups filters and exercise search. | Recent repeat tasks become easier without adding a new tab. |
| Profile scope | Goals, bodyweight, device controls and destructive data tools share one long page. | Group Training, Device and Data as three short sections; keep Reset behind a disclosure. | Matches how users look for settings and reduces accidental destructive actions. |
| Copy | Repeated “recommended,” “personalized,” “smart,” sparkles and “new” badges can make the interface feel generated. | Use concrete statements: which muscles, what changed, what action happens next. Reserve badges for real exceptions. | Specific explanations carry more credibility than promotional labels. |
| Typography | Display fonts and large numerals currently appear on almost every card. | Reserve display type for page titles/session focus; use the body font for small data and controls. Keep a consistent 16/14/12 text scale. | Fewer competing display elements give the existing typography more character. |
| Spacing | Small cards, large cards and settings rows use varied internal gaps. | Standardize 16 px card padding, 12 px row gaps, 24–32 px section gaps and at least 44 px touch targets. | Consistency is more noticeable than adding new decoration. |
| Responsive layout | Several horizontal chips and dose labels can wrap awkwardly on small phones. | Keep essential labels short, preserve a minimum 44 px target and avoid hiding labels behind ellipses. Check 320/390/430 px widths. | A complete app must work at the smallest supported size. |
| Accessibility | Sheets previously did not trap keyboard focus. Some icons rely on context alone. | Maintain labelled dialogs, focus restoration, visible keyboard focus and text alternatives; audit contrast and large text on an actual phone. | Helps assistive technology and makes controls easier for everyone. Modal focus handling was improved here. |
| Motion | Repeated entrance animation on every card could feel template-like. | Use one short entrance per sheet and subtle state transitions. Honor reduced motion; do not add continuous decorative animation to training. | Motion communicates state instead of drawing attention to itself. |
| Privacy expectations | “Only you see photos” is too absolute when an AI provider processes them. | Explain local previews, explicit provider submission, deletion and backup scope in plain language at the point of use. | Accurate privacy copy builds more trust than broad assurances. Implemented for the new flow. |
| Reliability | A locally running PC is easy to confuse with a hosted app. | Show a quiet, actionable connection notice only when needed, distinguishing frontend connection from photo service availability. | Prevents a generic “fetch failed” from looking like lost training data. |

No color system, font family, navigation tab set, branding or overall visual style was replaced in this implementation.
